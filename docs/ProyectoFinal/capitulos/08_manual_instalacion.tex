\chapter{Manual de instalación}\label{cap:manual-instalacion}

Este manual describe cómo dejar en funcionamiento una estación de LSA Salud: los requisitos, la instalación con Docker Compose, las variables de entorno, la verificación de la primera ejecución, la operación diaria y la solución de los problemas más comunes. Está dirigido al personal técnico. El uso de las estaciones se explica en el capítulo~\ref{cap:manual-usuario}.

\section{Alcance y componentes}

En el PMV, servidor y clientes comparten la misma computadora. El \emph{servidor} son los contenedores de Docker Compose (frontend, backend, modelo de lenguaje y proxy) y los \emph{clientes} son dos pestañas o ventanas de Google Chrome, una por estación, abiertas en esa misma computadora (figura~\ref{fig:vista-fisica}). No se requiere ningún servidor central ni conexión entre estaciones. La sincronización de la conversación entre la Estación del Paciente y la de Recepción usa el propio navegador, por lo que ambas deben abrirse en el mismo navegador y perfil; no se admite, en esta versión, abrir una estación desde otro equipo de la red.

Las tecnologías que componen el sistema se detallan en la tabla~\ref{tab:tecnologias} y sus características técnicas en la tabla~\ref{tab:especificaciones}.

\section{Instalación con Docker Compose}

El procedimiento es el mismo en cada estación.

\begin{enumerate}
  \item Instalar Docker Desktop y Google Chrome, y verificar que Docker Desktop esté iniciado.
  \item Clonar el repositorio y ubicarse en su carpeta raíz:
\begin{lstlisting}[numbers=none, language=bash]
git clone https://github.com/santinohamada/Nexora.git
cd Nexora
\end{lstlisting}
  \item Construir y levantar los servicios:
\begin{lstlisting}[numbers=none, language=bash]
docker compose up --build
\end{lstlisting}
  \item Esperar a que termine. La primera vez demora varios minutos: se construyen las imágenes, se descarga el modelo \texttt{qwen2:1.5b}, se compila el frontend (que descarga los modelos de MediaPipe) y el backend descarga la voz Piper. Las ejecuciones siguientes son mucho más rápidas.
  \item Abrir \texttt{http://localhost:3000} en Google Chrome.
\end{enumerate}

Con \texttt{docker compose up -d} los servicios se ejecutan en segundo plano. El archivo \texttt{docker-compose.yml} define cinco servicios, descritos en la tabla~\ref{tab:servicios-compose}, de los cuales solo \texttt{proxy} publica un puerto en el equipo.

En Docker Compose se pasan como argumentos de construcción del servicio \texttt{web}, por lo que un cambio exige volver a construir con \texttt{docker compose up --build}; al ejecutar sin Docker pueden definirse en \texttt{web/.env.local}. Existen otras variables de ajuste fino del frontend y de la medición de latencia que no deben modificarse en una instalación normal.

\section{Ejecución sin Docker (desarrollo)}

Esta modalidad es útil para desarrollar o depurar. Requiere los componentes de la tabla~\ref{tab:req-desarrollo}. Desde la raíz del repositorio, en PowerShell:

\begin{lstlisting}[numbers=none, language=bash]
python -m venv venv
.\venv\Scripts\activate
pip install -r requirements.txt
cd web && npm install && cd ..
ollama pull qwen2:1.5b
\end{lstlisting}

La voz Piper debe descargarse manualmente: los archivos \texttt{es\_AR-daniela-high.onnx} y \texttt{es\_AR-daniela-high.onnx.json} del repositorio de voces de Piper en Hugging Face (carpeta \texttt{es/es\_AR/daniela/high}) se copian en la carpeta \texttt{voices/}. Los modelos de MediaPipe los descargan solos los comandos \texttt{npm run dev} y \texttt{npm run build}. Luego se abren tres terminales desde la raíz, con el entorno virtual activado en la del backend:

\begin{lstlisting}[numbers=none, language=bash]
ollama serve
python -m uvicorn app:app --port 8000
cd web && npm run dev
\end{lstlisting}

El backend debe lanzarse siempre desde la raíz del repositorio, porque resuelve \texttt{models/}, \texttt{voices/} y \texttt{dataset/} de forma relativa. En esta modalidad el sistema también se abre en \texttt{http://localhost:3000}, y el origen de la API es el puerto 8000.

\section{Verificación de la primera ejecución}

Para comprobar que la instalación funciona, se recomienda seguir esta lista:

\begin{enumerate}
  \item \textbf{Servicios activos.} \texttt{docker compose ps -a} debe mostrar \texttt{ollama}, \texttt{api}, \texttt{web} y \texttt{proxy} en ejecución; \texttt{ollama-pull} aparece finalizado (\emph{Exited (0)}).
  \item \textbf{Backend listo.} \texttt{docker compose logs api} debe incluir los mensajes \texttt{Custom LSTM Model loaded} y \texttt{Piper TTS Model loaded}. Si falta el segundo, el sistema funciona pero sin voz.
  \item \textbf{API accesible.} La dirección \texttt{http://localhost:3000/classes} debe devolver la lista de señas: \texttt{["cabeza","dolor","idle","respirar","yo"]}.
  \item \textbf{Inicio.} \texttt{http://localhost:3000} muestra la pantalla de inicio con las tarjetas de las estaciones.
  \item \textbf{Estación del Paciente.} En \texttt{/paciente} aparece el diálogo de consentimiento; al aceptarlo y permitir la cámara, se ve la imagen con el indicador \emph{EN VIVO} y el panel \emph{Top-3 Predicciones} se actualiza.
  \item \textbf{Estación de Recepción.} En \texttt{/recepcion}, en otra pestaña del mismo navegador, se ve la imagen de la cámara del paciente; un mensaje escrito y enviado aparece en la pantalla del paciente.
  \item \textbf{Traducción y voz.} Con las señas \emph{yo}, \emph{dolor}, \emph{cabeza} y las manos bajas al final, se obtiene la oración \emph{Me duele la cabeza.} y se escucha en voz alta.
\end{enumerate}

\section{Apertura de las estaciones}

\begin{enumerate}
  \item Abrir \texttt{http://localhost:3000/paciente} en Google Chrome y mover la ventana al monitor del paciente.
  \item Abrir \texttt{http://localhost:3000/recepcion} en otra pestaña o ventana \textbf{del mismo navegador} y moverla al monitor del personal.
  \item La primera vez, Chrome solicita permiso para usar la cámara (estación del paciente) y el micrófono (dictado de Recepción). Deben permitirse; si se bloquearon, se restablecen desde el ícono del candado junto a la dirección.
  \item El consentimiento del paciente se guarda en el navegador; para volver a preguntarlo hay que borrar los datos del sitio.
\end{enumerate}

Chrome puede mostrar la ventana de la estación en pantalla completa con la tecla F11 para el uso en el puesto de atención.

\section{Operación: detener, reanudar y actualizar}

\begin{lstlisting}[numbers=none, language=bash]
docker compose down            # apagar
docker compose up -d           # volver a iniciar sin reconstruir
docker compose logs -f api     # seguir los registros del backend
docker compose restart api     # reiniciar solo el backend
\end{lstlisting}

Los datos de la tabla~\ref{tab:volumenes} sobreviven al apagado. El comando \texttt{docker compose down -v} elimina además los volúmenes con nombre y obliga a volver a descargar la voz y el modelo de lenguaje, por lo que requiere conexión a Internet.

Para actualizar a una nueva versión del código:

\begin{lstlisting}[numbers=none, language=bash]
git pull
docker compose up --build -d
\end{lstlisting}

Antes de actualizar o migrar una estación conviene copiar las carpetas \texttt{dataset/}, \texttt{models/} y \texttt{data/}, que contienen las muestras, el modelo vigente y los reportes.

\section{Reentrenamiento y nuevas señas (Modo Captura)}

El Modo Captura es una herramienta interna del equipo técnico, no una estación de cliente. Se abre en \texttt{http://localhost:3000/captura} (figura~\ref{fig:man-captura}) y sirve para grabar muestras y reentrenar el modelo. No debe usarse durante una atención: mientras se entrena, el reconocimiento queda pausado y se lee \emph{Entrenando\ldots{} el reconocimiento está pausado.}

\figuraTP{manual/11_captura}{0.9\textwidth}{Modo Captura (herramienta interna del equipo)}{fig:man-captura}

\begin{enumerate}
  \item Completar \textbf{Tu nombre}, que forma parte del nombre del archivo (\texttt{<marca de tiempo>\_<nombre>.npy}); admite letras, números y guiones, hasta 32 caracteres.
  \item Elegir la seña a grabar. Para agregar una seña nueva, usar \textbf{Nueva seña} e ingresar su nombre (minúsculas, números y guion bajo, hasta 32 caracteres).
  \item Indicar las \textbf{Repeticiones} y presionar \textbf{Empezar}. Cada repetición tiene una cuenta regresiva y graba 45 cuadros en \texttt{dataset/custom/<seña>/}; los \emph{blendshapes} faciales se guardan en \texttt{dataset/custom\_blendshapes/}.
  \item Si la cámara procesó menos de 18 cuadros por segundo, la muestra se descarta con un aviso; se recomienda cerrar los programas que usen la GPU.
  \item Con muestras nuevas, presionar \textbf{Reentrenar modelo}. Al finalizar, el reconocimiento vuelve a estar disponible sin reiniciar el backend.
\end{enumerate}

También puede entrenarse desde la línea de comandos, con el entorno virtual activado y desde la raíz del repositorio:

\begin{lstlisting}[numbers=none, language=bash]
python train_lstm.py             # entrena y guarda models/lstm.pth
python train_lstm.py --cv 5      # validacion cruzada (no guarda el modelo)
python eval_model.py <directorio_dataset>   # evalua el modelo actual
\end{lstlisting}

Si se entrena fuera del botón y el sistema corre con Docker, hay que reiniciar el backend con \texttt{docker compose restart api} para que cargue el nuevo modelo. Si las muestras se comparten entre integrantes mediante una carpeta de Google Drive, debe esperarse a que termine la sincronización antes de entrenar; de lo contrario el modelo usa un conjunto incompleto.
\section{Pruebas automáticas}

El repositorio incluye pruebas de la API y de la interfaz. Las de interfaz usan Playwright, que levanta su propio backend (puerto 8000, que debe estar libre) y el frontend (puerto 3000), con una cámara y un micrófono virtuales de Chromium:

\begin{lstlisting}[numbers=none, language=bash]
cd tests\e2e
npm install
npx playwright install chromium
npx playwright test
\end{lstlisting}

Las suites se ejecutan de a una, nunca en paralelo, para no superponer los puertos. El detalle del procedimiento y de los prerrequisitos de cada suite está en \texttt{tests/README.md}.
